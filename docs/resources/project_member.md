# foundryx_project_member

Owns one direct grant. Existing grants require import, even when roles match.
Identity changes require replacement; role changes update the same grant.
Creation never falls back from conflict to role update.

```terraform
resource "foundryx_project_member" "your-group" {
  project_id     = var.your-project-id
  principal_type = "group"
  principal_id   = var.your-group-id
  role           = "user"
}

variable "your-project-id" {
  type        = string
  description = "UUID of an existing FoundryX registration."
}

variable "your-group-id" {
  type        = string
  description = "Existing group object UUID in the provider tenant."
}
```

## Schema

### Required

- `principal_id` (String) Entra principal UUID; tenant grants require the provider tenant UUID.
- `principal_type` (String) user, group, or tenant (all users in this tenant).
- `project_id` (String) FoundryX project UUID.
- `role` (String) consumer, user, manager, or owner. Tenant-wide grants support consumer and user only.

### Read-Only

- `id` (String) Tenant-bound Terraform import identifier.



## Import

```terraform
import {
  to = foundryx_project_member.your-group
  id = "${var.your-tenant-id}/${var.your-project-id}/group/${var.your-group-id}"
}
```

Import only reads the direct grant. Different configured roles appear as explicit
updates in the next plan. Group or tenant-wide inheritance is not a direct user
grant. User, group, project, and tenant identifiers must be canonical UUIDs.

`principal_type = "tenant"` grants access to **all users in the tenant**.
Its `principal_id` must equal provider `tenant_id`; supported roles are `consumer`
and `user`. User and group grants additionally support `manager` and `owner`.
The server remains authoritative for the caller's assignable roles.

Deleting a member revokes only that direct grant, preserving registration,
policy, and unrelated grants. Effective access can continue through other grants.
Updates retain portal behavior and have no stale-plan protection.

Creation atomically rejects an existing direct grant, even when its role matches.
Mutations are not automatically replayed after an ambiguous failure. If the grant
was created but Terraform did not save state, inspect it and use Terraform import
before applying again. No request ID is needed in configuration.
