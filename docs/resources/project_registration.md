# foundryx_project_registration

Creates a deny-all FoundryX registration, not a native Azure project. Existing
registrations require import. ARM identity changes require replacement;
case-only spelling changes do not.

```terraform
resource "foundryx_project_registration" "your-project" {
  project_arm_id = var.your-project-arm-id
}

variable "your-project-arm-id" {
  type        = string
  description = "ARM ID of an existing Foundry project; no native resources are created."
}
```

## Import

```terraform
import {
  to = foundryx_project_registration.your-project
  id = "${var.your-tenant-id}/${var.your-project-id}"
}
```

The tenant must match the provider. Import reads identity and lifecycle metadata
without changing policy, membership, or service access.

## Recovery and removal

Creation atomically rejects an existing registration instead of adopting it.
There is no durable create-request history or automatic replay after a lost
response. If creation succeeds but Terraform does not save state, inspect the
registration and use Terraform import before applying again.

Incomplete setup or `monitoring_error` produces an explicit diagnostic. Finish
incomplete setup through the FoundryX import workflow before importing into
Terraform, or remove the incomplete access and retry. Review any retained partial
state and replacement plan before applying.

Removal invokes the portal's **Remove access** operation with exact-name
confirmation. It removes all FoundryX project grants, including grants owned
outside this configuration, and reuses resumable, shared-assignment-aware API
cleanup. Native Azure projects, Agents, deployments, connections, and tools
remain. Refused or incomplete removal retains Terraform state.

Hand off any managed policy explicitly before destroying registration; see the
[policy resource](project_policy.md).
