# foundryx_project_policy

A logical singleton while registration exists. Owns both complete allowlists,
not policy description or native resources. Explicit empty sets deny all.
Missing policy storage and explicitly empty policy read identically.
Set order has no meaning; deployment and tool names remain case-sensitive.

```terraform
resource "foundryx_project_policy" "your-policy" {
  project_id     = var.your-project-id
  allowed_models = ["your-deployment"]
  allowed_tools  = ["builtin:web_search"]
}

variable "your-project-id" {
  type        = string
  description = "UUID of an existing FoundryX registration."
}
```

## Import

```terraform
import {
  to = foundryx_project_policy.your-policy
  id = "${var.your-tenant-id}/${var.your-project-id}"
}
```

Import reads effective lists without changing access. A subsequent configuration
difference produces a reviewed policy update. PATCH preserves the description.
Changes made after planning may be overwritten; stale-plan protection is deferred.

## Unsupported deletion

The portal has no Delete policy action. Deleting this resource, including through
one-step destroy, fails without changing access or dropping state. Updating both
lists to `[]` is supported but is not deletion.

To hand off the policy, replace its resource block with:

```terraform
removed {
  from = foundryx_project_policy.your-policy
  lifecycle {
    destroy = false
  }
}
```

Keep registration and memberships configured and apply this explicit state-only
handoff first. Then registration destruction removes the underlying policy with
all other FoundryX project access. This cleanup requires Terraform 1.7 or later.
